## Context

QA verifies a tooling-only change: vendored Cypress skills, a shared support
layer, and a CI workflow. No game behaviour or presentation should change.

## Objective

Confirm that the suite is genuinely stabilised, that assertions were not
weakened, that the pipeline matches the approved design, and that no game
source or production behaviour changed.

## In scope

- Skill contents, pinning, licence, and project-skill accuracy.
- Support commands and their types.
- Removal of duplicated helpers and manual polling.
- Remaining raw waits and their justification.
- Config, script, and workflow behaviour.
- Full typecheck, unit, build, and repeated e2e results.
- Production bundle unchanged in behaviour (no debug hook leakage).
- Git history and commit scope.

## Out of scope

- Cypress Cloud, `cy.prompt()`, component testing, sharding.
- Game balance or visual review; no game code is in scope.

## Acceptance criteria

1. `npm run typecheck`, `npm test`, and `npm run build` pass on a clean
   install.
2. `CYPRESS_BROWSER=chrome npm run e2e` passes three consecutive times.
3. The suite still has 15 tests and the same covered behaviours as `0.2.0`.
4. No assertion was removed or weakened; any test change is explainable as a
   synchronisation or reliability improvement.
5. Both specs interact only after the debug hook exists.
6. Shared commands are typed, reusable, and used by both specs.
7. No manual snapshot/poll loop remains in the specs.
8. Every remaining raw wait has a comment proving it is input duration or the
   frozen-run check.
9. `.github/workflows/e2e.yml` runs typecheck, unit tests, and e2e, uses Node
   22, runs on PRs/pushes to `dev`, and uploads failure artifacts.
10. Skills are pinned, licensed, and documented; `cypress-cloud-cli` is
    deliberately absent.
11. `src/`, `public/`, and the production bundle have no functional change and
    no `__gameDebug` leakage.
12. Every finding has severity, reproduction, expected vs actual, evidence,
    owner, and required rerun.

## Dependencies and handoff

Inputs: approved design decisions, programmer implementation log, tested
commit.
Outputs: QA report with a `Passed`, `Changes requested`, or `Blocked` verdict,
tested commit, commands, evidence, residual risks, and the report commit hash.

## Open assumptions / unresolved items

- Hosted CI has not run yet; QA verifies the workflow definition and the same
  commands locally, and records the first hosted run as an operator follow-up.
