## Context

`0.5.0` is merged. Boot currently waits for sprite loading with no visible
progress, and audio starts downloading only after the first gesture. The
`0.6.0` task adds a boot loading screen, complete image/audio/font preload,
and the approved Grenze Gotisch display typeface. Loading, title, restart,
descent, and audio unlock behaviour must remain compatible with the existing
game and e2e suite.

## Objective

Independently verify that the loading screen reports real boot progress,
that the title appears only after the approved assets and font are ready,
that audio is preloaded and unlocks safely, that the font is correctly
self-hosted and applied, and that gameplay and existing flows have not
regressed.

## In scope

- Cold-load loading-screen visibility, layout, copy, progress, and fade.
- Progress monotonicity, readiness gating, minimum display time, and boot
  debug state.
- Complete image and audio preload; audio manifest coverage.
- Suspended-context preload, gesture unlock/resume, ambient start, and
  buffer readiness.
- Audio failure, unsupported-context, and missing-file degradation.
- Image failure and the boot error state.
- Font loading, local hosting, license/attribution, display application, and
  fallback.
- Accessibility: progressbar semantics, reduced motion, no skip, no input
  forwarding.
- Boot-only behaviour on restart and descent.
- Regression checks for title, pause, death, combat, purification, boss,
  descent, and audio cues.
- Typecheck, unit, build, e2e, production-bundle, and external-request
  checks.
- Git history and commit scope.

## Out of scope

- A subjective art review beyond the approved design decisions.
- Gameplay balance tuning or new feature requests.
- Hosted CI execution; GitHub owns that verification.
- Vercel deployment verification.
- Mobile/touch layout.

## Acceptance criteria

1. `npm run typecheck`, `npm test`, `npm run build`, and
   `CYPRESS_BROWSER=chrome npm run e2e` pass from a clean dependency state.
2. A cold load shows the loading screen before the title. The title is not
   interactive while the overlay is visible.
3. The progressbar exposes a value that never decreases and reaches 100 only
   after all images, all audio-manifest files, and the font have settled.
4. The loading screen remains visible for at least the approved minimum and
   fades into the title on success.
5. Every audio file used by the game is in the boot manifest; the loaded
   buffer count matches the manifest after preload, including
   `cloth1–4.ogg` and `creak2.ogg`.
6. The first gesture resumes the audio context, the ambient loop starts, and
   at least one gameplay cue plays from an already-loaded buffer.
7. When `AudioContext` is unavailable or a file fails, boot completes, the
   title is reachable, and gameplay remains fully playable and readable.
8. A failed image after the existing retries produces the readable boot
   error instead of entering the title with missing assets.
9. Grenze Gotisch is served from `public/assets/fonts/`; the OFL license and
   attribution are present; no external font/CDN request is made. Display
   surfaces use it and fall back to `system-ui`.
10. The loading screen respects `prefers-reduced-motion`, has no skip action,
    and does not forward input to the game before the title.
11. Restart (`R` after death) and floor descent do not replay the loading
    screen.
12. Existing title/pause/death/combat/purification/boss/descent behaviour
    passes the existing suite with no assertion removed without replacement.
13. The production bundle contains no `__gameDebug`, `__audioDebug`, or
    `__bootDebug` hooks.
14. The diff contains no gameplay-rule or balance changes beyond what the
    approved design requires.
15. Every finding has severity, reproduction, expected vs actual, evidence,
    owner, and required rerun.

## Dependencies and handoff

Inputs: approved design decisions, programmer implementation log, tested
commit.

Outputs: QA report with a `Passed`, `Changes requested`, or `Blocked` verdict,
tested commit, commands, evidence, residual risks, and the report commit
hash.

## Open assumptions / unresolved items

- Hosted CI and deployment remain pending on GitHub/Vercel and are recorded
  as such rather than claimed locally.
- Headless audio output is not asserted; audio readiness is verified through
  debug state, manifest counts, and source inspection.
- A blocked image request may require a manual DevTools request-blocking
  check because Cypress does not intercept image elements; this is recorded
  as manual evidence.
- Visual verification uses browser screenshots at 1024 × 640 and 1440 × 810.
