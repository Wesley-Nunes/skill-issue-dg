## Context

QA verifies the re-based `0.2.0` liberation loop independently of the programmer's description. The combat foundation (combo, enemies, projectiles, camera, death/restart) is retained; the reward loop is replaced by spirit fragments, respawn, permanent rest, a spirit meter, and a floor-purified overlay.

## Objective

Confirm that the implementation matches the approved purification rules and design values, that removed scope is actually gone, and that retained combat behavior still works.

## In scope

- Fragment layout, break, restoration, and ready-to-rest presentation.
- Conventional-death respawn timing and reset state.
- Permanent rest, spirit gain, and the no-respawn rule.
- Spirit meter values, placement, and fill.
- Floor-purified freeze, overlay text, and `R` restart.
- Removal of skill points, challenge, notice, room clear, and drops.
- Regression coverage for `0.1.0` movement, dodge, camera, HP, death, restart, and the hard-timed combo.

## Out of scope

- Boss, floors, scaling, drops, inventory, currency, shops, persistence, audio, menus.
- New balance tuning beyond the approved values.

## Approved behavior to verify

1. Two fragments per mob at the approved orbit positions, size, colour, and bob.
2. A light-attack step breaks every intact fragment inside its arc; outside fragments stay.
3. Breaking a fragment counts as a connected combo step.
4. Any HP loss restores all broken fragments on every living mob; blocked damage and dodges do not.
5. Restoration does not reset the mob's HP.
6. A mob killed with intact fragments fades and respawns after 2 s at its spawn with full HP and fragments.
7. A mob killed with all fragments broken rests permanently, grants 34 spirit once, and never respawns.
8. Fragments resolve before damage on the same swing.
9. Spirit clamps at 100, freezes the run, and shows the purified overlay.
10. `R` clears spirit, fragments, respawn, rest flags, and restores the initial room.
11. No skill-point, challenge, notice, room-clear, or drop behavior remains.

## Constraints

- Use the repository's existing scripts and tooling; do not add QA dependencies.
- Do not change application code as QA; return findings to the owner.
- Verify the actual code and behavior rather than accepting the CoT.

## Acceptance criteria

1. All automated checks pass on a clean install: `npm run typecheck`, `npm test`, `npm run build`, `npm run e2e`.
2. Each approved behavior above has a unit or browser test, or documented manual evidence.
3. The production bundle contains no `__gameDebug` reference.
4. Design values in the config and renderer match `design/0.2.0/design-decisions.md` §9.
5. Removed scope is absent from source, tests, HUD, and bundle behavior.
6. Visual evidence covers fragments, the spirit HUD, the ready-to-rest cue, and the purified overlay (or the overlay is verified by code inspection with the reason recorded).
7. Retained `0.1.0` and combo regressions pass.
8. Every finding has severity, reproduction, expected vs actual, evidence, owner, and required rerun.
