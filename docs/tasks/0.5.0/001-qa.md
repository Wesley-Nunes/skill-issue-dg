## Context

The `0.5.0` release adds a floor boss summoned by a full spirit meter, a bomb
attack, Web Audio, a title/pause/death flow, heal-on-descent, and a deployable
build. The existing `0.4.0` loop must keep working.

## Objective

Independently verify the boss loop, bomb readability and damage, audio
unlock/mute behavior, title/pause/death flow, heal-on-descent, deployment
configuration, and regressions in the existing combat, purification,
generation, and descent behavior.

## In scope

- Boss summon, stats, melee, bomb, defeat, and stairs unlock.
- Bomb flight, landing, fuse, explosion, dodge/i-frame avoidance, and cleanup.
- Spirit meter and HUD states: sealed, boss awakened, stairs open.
- Title/start, pause/resume, death summary, and restart.
- Heal 2 HP on descent, cap, and HP preservation.
- Audio unlock, ambient, event cues, mute toggle, and safe degradation.
- Unit, build, typecheck, and e2e results.
- Production bundle has no debug hooks.
- README and Vercel configuration.
- Git history and commit scope.

## Out of scope

- Safe rooms, shops, currency, loot, artifacts, multiple bosses, difficulty
  scaling, floor themes, persistence, meta-progression.
- A subjective audio/art review beyond the approved design decisions.
- Hosted CI execution; GitHub owns that verification.
- Vercel account setup; the operator owns the project connection.

## Acceptance criteria

1. `npm run typecheck`, `npm test`, and `npm run build` pass from a clean
   dependency state.
2. `CYPRESS_BROWSER=chrome npm run e2e` passes and no assertion is removed
   without a replacement covering the same player-visible behavior.
3. Resting every non-boss mob spawns exactly one boss, sets `bossAwake`, keeps
   the stairs sealed, and emits `boss-summoned`.
4. The boss takes combo damage, does not rest or respawn, and is not knocked
   back by the finisher.
5. The boss performs both a melee attack and a bomb attack; the bomb lands,
   fuses, explodes, and damages a player inside the blast.
6. A dodge or i-frame prevents bomb damage.
7. Defeating the boss opens the stairs, clears `bossAwake`, and emits
   `boss-defeated`; stepping on the stairs descends.
8. Descent heals 2 HP, caps at max, preserves HP otherwise, resets spirit and
   boss state, and increments depth.
9. The app starts on a title screen; click/Enter/Space starts; Escape pauses
   and resumes; the simulation does not advance while title/paused.
10. Death shows depth and purified-mob count; `R` restarts at depth 1.
11. Audio unlocks on the first gesture, plays mapped cues, toggles with `M`,
    and does not break play when Web Audio is unavailable.
12. The production bundle contains no `__gameDebug` or `__audioDebug`.
13. `README.md` documents controls, commands, stack, attribution, and the
    Vercel `dev`/`main` mapping; `vercel.json` is valid.
14. Every finding has severity, reproduction, expected vs actual, evidence,
    owner, and required rerun.

## Dependencies and handoff

Inputs: approved design decisions, programmer implementation log, tested
commit.

Outputs: QA report with a `Passed`, `Changes requested`, or `Blocked` verdict,
tested commit, commands, evidence, residual risks, and the report commit hash.

## Open assumptions / unresolved items

- Hosted CI and Vercel deployment are verified by the operator after the
  branch is pushed; QA records them as pending rather than claiming a hosted
  result.
- Audio is verified through debug state and manual listening; headless audio
  output is not asserted.
- Visual verification uses canvas screenshots/state captures; there is no
  separate art review.
