## Context

The implemented slice replaces the single fixed room with a seeded floor of
four connected rooms. It adds stairs, floor descent, tile collision, and a
depth/exit HUD, and removes the run-ending purified freeze.

## Objective

Independently verify that the generated floor is traversable and
deterministic, that the exit/descent loop works without regressing combat or
purification, and that presentation matches the design decisions.

## In scope

- Generator determinism, room count, connectivity, walkable spawn/stairs.
- Tile collision for player, enemies, and projectiles.
- Camera clamping to generated bounds across viewport sizes.
- Enemy distribution and existing combat/purification behaviour.
- Exit locking, unlock condition, no-freeze behavior, and descent.
- HP preservation, spirit reset, depth increment, new-floor generation.
- HUD, stairs states, and removal of the purified overlay.
- Unit, build, typecheck, and e2e results.
- Production bundle has no debug hook.
- Git history and commit scope.

## Out of scope

- Safe rooms, shops, currency, loot, boss, difficulty scaling, floor themes,
  audio, menus, persistence.
- A visual/art-direction review beyond the approved design decisions.
- Hosted CI execution; GitHub owns that verification.

## Acceptance criteria

1. `npm run typecheck`, `npm test`, and `npm run build` pass from a clean
   dependency state.
2. `CYPRESS_BROWSER=chrome npm run e2e` passes and no assertion is removed
   without a replacement covering the same player-visible behavior.
3. The same seed produces the same floor; different seeds produce different
   room dimensions/spacing or enemy/stairs placement.
4. A floor has four rooms, and a walkable path exists from spawn to stairs.
5. The player spawn, all enemy spawns, and the stairs are walkable.
6. The player, enemies, and projectiles cannot enter solid tiles; the camera
   stays inside the floor at 1024×640 and 1440×810.
7. Three enemies spawn, one in each non-start room; the default composition
   is two melee and one ranged.
8. The exit is locked while any enemy is not rested and opens when all are
   rested. Opening it emits `floor-purified` and does not freeze the run.
9. A conventionally killed, unrested enemy still respawns and keeps the exit
   locked.
10. Stepping on unlocked stairs increments depth, regenerates the floor,
    resets spirit and projectiles, preserves player HP, and updates the HUD.
11. The HUD shows depth and stairs status; no purified overlay or
    `"purified"` status remains.
12. The production bundle contains no `__gameDebug`.
13. Every finding has severity, reproduction, expected vs actual, evidence,
    owner, and required rerun.
